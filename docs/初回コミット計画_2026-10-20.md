## 共著トレーラーとリポジトリ名の確認（2026-10-21 追記）

**`Co-authored-by:` は2行以上併用できる。** GitHub 公式ドキュメントは「共著者ごとに1行」と定めており、人数の上限はない。git 側（`git interpret-trailers`）でも2行が正しく解釈されることを確認した。既存リポジトリの初回コミット（Codex 1行）は GitHub 上で署名 `verified: true` のまま共著が認識されている。したがって本リポジトリの文案（Codex と Claude の2行）はそのまま使える。

**既存の8リポジトリへの適用**：過去のコミットに Claude の行を足すには履歴の書き換え（amend と force push）が必要で、コミットIDが変わる。また、それらのコミットは Claude が内容に関与していないので、足すと事実と合わない。運用は「次のコミットから、実際に関わった AI の行を付ける」とし、各リポジトリの AGENTS.md に共通節（上の文案）を1コミットで追記する。その追記コミット自体は、文案を Claude が書いたので `Co-authored-by: Claude Fable 5.1 <noreply@anthropic.com>` を付ける（Codex が関与しなければ Codex の行は付けない）。

**リポジトリ名は ASCII に限られる。** GitHub のリポジトリ名に使えるのは英数字と `.` `-` `_` で、日本語を入力すると自動でハイフンに置き換えられる（作成画面の名前欄に「卒業プロジェクト」と入力すると、作成前に置換後の名前が表示されるので、作らずに確かめられる）。日本語で揃えられるのは、他リポジトリと同じく **説明文（日本語1文）と README の題名** まで。既存8リポジトリはフォルダ名とリポジトリ名が一致しているので、名前を決めたらローカルのフォルダも同じ名前に変えると揃う（変えると `.venv` と Claude のメモリの対応先が再びずれるが、`.venv` は既に不要、メモリは複製で対応できる。仮想環境 `.venvs/` はフォルダ名を決めてから作る）。

## submodule とは

- **何をするか**：別のリポジトリ（広聴AI）の「特定のコミット」を、自分のリポジトリの中の決まったフォルダ（`vendor/kouchou-ai`）に結びつけて記録する仕組み。自分のリポジトリには広聴AIのファイル本体は入らず、「このURLのこのコミット」という1行の参照だけが入る（`.gitmodules` ファイルと、コミットIDの記録）。
- **再現性にどう効くか**：読者が `git clone --recurse-submodules` するか、clone 後に `git submodule update --init` を実行すると、まったく同じコミットの広聴AIが `vendor/kouchou-ai` に展開される。README にコミット番号を書くだけの方法と違い、git が機械的に保証する。
- **ライセンス**：広聴AIは AGPL-3.0 だが、submodule は複製ではなく参照なので、本リポジトリのライセンス（MIT / CC BY）に影響しない。`vendor/` 内を改変しない方針とも合う。
- **注意点**：
  - submodule の中で `git pull` や `checkout` をすると参照先が変わる。本研究では固定なので、触らない。
  - `git status` で `vendor/kouchou-ai` に `(new commits)` や `modified content` と出たら、参照がずれたか中身を変えた印。`git submodule update` で固定コミットに戻せる。
  - GitHub 上では `vendor/kouchou-ai @ eb38328` というリンク表示になり、クリックすると元リポジトリのそのコミットに飛ぶ。
- **今の状態からの登録**：`vendor/kouchou-ai` はすでに同じURLのクローンで HEAD が固定コミットなので、`git submodule add <URL> vendor/kouchou-ai` を実行すると、そのまま submodule として登録される（再ダウンロードはない）。`.gitignore` の `vendor/` の行を先に消す。
